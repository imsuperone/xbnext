# XBNEXT · 开发规范（红线门禁）

> **优先级**：本文件红线 > 用户当次指令 > AI 自行判断。
> 红线明写"勿改动 / BY DESIGN"的，只确认、不修改。
> 每条红线都有出处（工作区 skill / AstrBot 官方原则 / 本项目决策）。

---

## 1. 硬红线（违反即返工）

| # | 红线 | 出处 |
| :-: | :--- | :--- |
| 1 | 持久化数据存 `data` 目录（插件 KV 或 `data/plugin_data/<插件名>/`），**绝不存插件自身目录** | AstrBot 官方开发原则 3 |
| 2 | 网络请求只用异步库（`httpx/aiohttp`），**禁 `requests`**；确实要用 stdlib 时（如 `urllib`）必须包在 `asyncio.to_thread` 里，**绝不在事件循环里同步阻塞** | AstrBot 官方原则 6 |
| 3 | 日志只用 `from astrbot.api import logger`，**禁 `logging`** | AstrBot 官方 |
| 4 | 动态提示词（每轮变化的内容）**禁写 `req.system_prompt`**，一律 `extra_user_content_parts + mark_as_temp()` | AstrBot 官方警告（会破坏 prompt cache，成本涨 7-20 倍） |
| 5 | 注入的身份/档案/引用字段必须过 `sanitize`（控字符→空格、去零宽、`<>` 全角、截断），防提示词注入 | AstrNa identity_metadata.py:486-493 |
| 6 | 身份匹配/引用匹配**歧义即放弃，不猜人** | 本项目（猜错 = R1 bug 本体） |
| 7 | 所有 LLM 注入只经 `xbnext/injector.py`，模块不得自行构造 TextPart | 本项目架构 |
| 8 | 单模块内**任何异常降级为日志 + 安全默认值**，不裸抛（一个错误不能崩插件） | AstrBot 官方原则 4 |
| 9 | WebUI 文件放 `pages/<name>/` 并在 `metadata.yaml` 的 `pages:` 声明 `name/title/path` | 工作区 skill §3（xbdoc/beta 省略 pages 是反面教材，xbimg 是正例） |
| 10 | `_conf_schema.json` 每个配置项必须有 `type`；object 用 `items` 嵌套 | 工作区 skill §3 |
| 11 | 文本文件一律 **UTF-8 无 BOM**；PowerShell 读写加 `-Encoding utf8`，跑 Python 加 `-X utf8` | 工作区环境约束（GBK 乱码史） |
| 12 | 函数内懒导入用 `from .X` 优先、`from core.X` 回退的双兼容写法（若需要） | 工作区 skill §3 |
| 13 | **日志不刷屏**：每轮只在"真有动作"时打一条 INFO 汇总（`本轮 …`），无动作一行不打；逐条明细只在 `debug_log` 落 DEBUG | 本项目（真机第二轮反馈） |
| 14 | 早期钩子（`event_message_type(ALL)`）**整体异常自吞** —— AstrBot `call_handler` 会把钩子异常变成一条发给用户的消息 | 本项目（`pipeline/context_utils.py::call_handler`） |
| 15 | 动态改写 `event.message_str` 必须有守卫：正文为空 && `is_at_or_wake_command`，否则会改用户正文或让 bot 回每条消息 | 本项目（aidoc/01 §3.1 证据④⑤） |
| 16 | 后台常驻任务（如表情表自动更新循环）：**首次动作必是 ≥60s 的 sleep**（测试里 `asyncio.run` 退出即取消，永不触网）、网络只走 `asyncio.to_thread`、`CancelledError` 原样上抛其余**异常一律不上抛**（只打 WARNING + 短睡防紧循环）、`on_unload` 只 `cancel()` **绝不跨 loop await** | 本项目（`face/__init__.py::_update_loop`，AstrBot 原则 4） |

## 2. 版本号规则

- **semver**，起步 `0.1.0`；次版本满 99 或用户明示才升段。
- 三处必须一致（每次发版同步改）：
  1. `metadata.yaml` → `version: "x.y.z"`
  2. `CHANGELOG.md` → 首条 `## vx.y.z`
  3. `README.md` → 版本行
- 禁止在 Python 代码里硬编码版本字面量（要显示版本就读 metadata.yaml，
  照 AstrNa `main.py::_read_plugin_version()` 的做法）。
- 改完跑自检，不凭眼睛核对。

## 3. 自检（每次交付必跑并贴结果）

```powershell
# 1) Python 编译（全量语法检查）
python -X utf8 -m compileall -q main.py xbnext tests

# 2) 单测（**不依赖 astrbot**，本机没装 AstrBot 也能跑）
python -X utf8 -m unittest discover -s tests

# 3) 前端 JS 语法（改了 pages 才跑，每个 js 都要）
Get-ChildItem pages -Recurse -Filter *.js | %{ node --check $_ }
```

期望：compileall 无输出退出码 0；unittest 打印 `OK` 且 `$LASTEXITCODE -eq 0`；
`node --check` 无输出。

> PowerShell 会把 stderr 上的测试进度当成错误红字，**看 `OK` 和退出码**，
> 不要被红字误导。本机未安装 pytest，统一用标准库 `unittest`。

工作区一键全量（覆盖 5 个老插件）：

```powershell
# 路径相对**工作区根目录**（xbnext 仓库的上一级）
powershell -File ..\.opencode\skills\astrbot-plugin-dev\scripts\check-all.ps1
```

该脚本的默认插件列表**不含 xbnext**；要带上得显式传参，
而且它对 xbnext 只跑 `compileall` + `node --check`（没有 xbnext 的门禁分支），
**单测仍要单独跑上面第 2 步**：

```powershell
powershell -File ..\.opencode\skills\astrbot-plugin-dev\scripts\check-all.ps1 -Plugins astrbot_plugin_xbnext
```

xbnext 没有自己的门禁脚本，交付前以本节 1)~3) 为准。

**交付说明必须写明"未做真机回归"**（AstrBot 在云端，本机无法验证安装后运行）。

## 4. 编码风格

- 中文注释讲"为什么"，不复述代码；关键模块顶部写模块职责块。
- 单文件控制在 ~800 行内，超了就拆（AstrNa 的 40-80KB 大文件是反面参考，
  它的 tests 齐全才扛得住，我们规模小更要拆）。
- 命名：模块 `snake_case.py`、类 `PascalCase`、常量 `UPPER_SNAKE`；
  私有内部字段单下划线 `_x`。
- async 优先；钩子内禁止长时间同步阻塞（AstrBot 主循环零阻塞原则）。
- 不引入第三方运行时依赖（除非必要；若引入必须写 `requirements.txt`）。

## 5. 指令规范

- 统一挂 `@filter.command_group("xbnext")`，子指令 `xbnext.xxx`，
  避免与别的插件顶层指令撞名。
- 指令 handler 必须带 docstring（AstrBot 会解析展示给用户）。
- 管理员指令加 `@filter.permission_type(filter.PermissionType.ADMIN)`；
  **非超管发超管指令保持静默**（工作区红线 7 的设计哲学，别加提示）。

## 6. 提交与发布

- `astrbot_plugin_xbnext` 是独立 git 仓库（remote 已配
  `github.com/imsuperone/xbnext`，main 分支），提交、push、打 tag 都要 `cd` 进来做。
- 提交信息格式：`<type>: <中文简述>`，type ∈ feat/fix/docs/refactor/test/chore。
- 发版流程：CHANGELOG 写小节 → 改三处版本 → 跑自检 → commit → push → tag `vx.y.z`。
- `aidoc/` **不进发布包**（打包时排除），但**必须进 git**（团队资产）。
