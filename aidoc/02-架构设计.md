# XBNEXT · 架构设计

> 版本：v0.1（设计稿，随实现更新）
> 原则：干净、精简、规范；每个模块单一职责；所有 LLM 注入走统一通道。

---

## 1. 分层结构

> 本节与仓库实际结构保持一致（P1 已落地）。**改结构必须同步改这里。**

```
astrbot_plugin_xbnext/
├─ main.py                 Star 入口：装配 runtime、注册钩子与指令（薄壳，只转发）
├─ metadata.yaml           插件元数据（含 pages 声明；**版本号唯一来源**）
├─ _conf_schema.json       配置 schema（每功能一个 enable_* 主开关 + condition 子项）
├─ xbnext/                 业务包
│  ├─ __init__.py          版本号（读 metadata.yaml）、PLUGIN_NAME、HOOK_PRIORITY
│  ├─ runtime.py           调度中心：每请求对账开关、按固定顺序调用各功能
│  ├─ context.py           RequestContext：单次请求上下文（功能只跟它打交道）
│  ├─ injector.py          统一注入工具：temp part 构造 + sanitize + strip + wrap
│  ├─ inject_log.py        P16 注入记录：纯函数 + KV（10 轮环形，WebUI 入口读）
│  ├─ switches.py          开关对账 + WebUI 配置写入（转型 / 落盘 / 回滚）
│  ├─ storage.py           插件 KV 封装：前缀 / 缓存 / 写穿 / 异常降级
│  ├─ config.py            配置读取（含 _conf_schema.json 默认值回退）
│  ├─ commands.py          指令文本解析（纯函数，兜住 AstrBot 剥前缀的多种形态）
│  ├─ features/            ★ 功能模块 —— **一功能一目录，新增功能只改这里**
│  │  ├─ base.py           Feature 基类 + 扩展步骤说明
│  │  ├─ __init__.py       注册表 FEATURES（加功能 = 这里加一行）
│  │  ├─ quote/            R2 引用占位清洗  （service.py 纯逻辑 + __init__.py 功能类）
│  │  ├─ face/             R3 QQ 表情翻译   （service.py 纯逻辑 + data.py 表情表）
│  │  ├─ attribution/      R1 回复指向索引  （service.py 注入文案 + store.py KV 索引）
│  │  ├─ profile/          R4 用户档案      （service.py 指令语法 + store.py 存储/渲染）
│  │  └─ recall/           R6 撤回取消请求  （service.py 纯识别 + 早期钩子登记/命中）
│  └─ web/                 WebUI 后端 API（ping / state / setting / profiles / inject_log）
├─ pages/manager/          R5 WebUI（xbimg 形态：index.html + style.css + api.js + app.js）
├─ tests/                  单测（unittest，**不依赖 astrbot**）
└─ aidoc/                  本文档（不进发布包，必须进 git）
   └─ tools/               生成器脚本（如 gen_face_table.py，随 aidoc 排除出包）
```

**为什么功能用目录而不是单文件**：功能会长大（R1 要 store + 注入文案、
R3 要 service + 权威表情表、R4 要 store + 指令），单文件会膨胀到 AstrNa
那种 40-80KB 大文件。一功能一目录后，每个功能自成一块，拆分边界天然清晰。

**新增功能的 5 步**（写在 `features/base.py` 顶部注释里）：

1. 建 `features/my_thing/`，写 `class MyThingFeature(Feature)`；
2. 填 `key` / `name` / `description` / `order`，实现 `on_llm_request`；
3. `_conf_schema.json` 加 `enable_my_thing`；
4. `features/__init__.py` 的 `FEATURES` 加一行实例化；
5. `tests/` 加 `test_my_thing.py`。

**可选 · 暴露子指令**（像 `/xbnext profile` 那样，见第 3 节）：功能里填
`command = "mything"` 并实现 `async def handle_command(self, event, args, conf) -> str`；
再在 `main.py` 加一个静态 `@xbnext.command("mything")` 转发到
`runtime.handle_command(...)` —— AstrBot 的指令扫描发生在类加载期，子命令
必须静态写在那里，动态挂载不可靠。

第 3、4 步有机械校验兜底（`tests/test_structure.py`：功能 key 必须在 schema 里、
schema 的 `enable_*` 必须有对应功能、执行顺序必须升序），漏做直接红。

## 2. 钩子与调用时序

XBNEXT 用到的 AstrBot 钩子（全部 `priority` 统一用一个常量
`xbnext.HOOK_PRIORITY`，避免不同钩子跑到不同先后顺序）：

| 钩子 | 用途 | 所属模块 |
| :--- | :--- | :--- |
| `@filter.event_message_type(ALL)` | **早期钩子**：core 判定「空消息」之前补写 `message_str`（纯表情救生索）+ 撤回任务登记/命中（R6） | R3 / R6 |
| `@filter.on_llm_request` | 主战场：表情翻译、引用清洗、身份/档案注入、回复指向说明 | 全部 |
| `@filter.after_message_sent` | 记录本轮 bot 回复 → 写回复指向索引 | R1 |
| `@filter.on_astrbot_loaded` | 初始化存储、加载映射表 | 全部 |
| `@filter.command` | `/xbnext ...` 单指令入口，`runtime.dispatch` 统一分发（菜单/状态/档案/未知提示） | R4 |
| `terminate()` | 卸载时释放资源 | 全部 |

### 2.1 priority 方向（已从 core 源码查实，不再是"待实测"）

`astrbot/core/star/star_handler.py::star_handlers_registry.append()`：

```python
self._handlers.sort(key=lambda h: -h.extras_configs["priority"])
```

`get_handlers_by_event_type()` 按 `_handlers` 原序返回 ⇒ **按 priority 降序执行，
数值越大越靠前**。

| 插件 | `event_message_type(ALL)` | `on_llm_request` |
| :--- | :--- | :--- |
| 内置星标 `astrbot/builtin_stars/astrbot/main.py` | `maxsize` / `maxsize-1` | — |
| **xbnext** | **1000** | **1000** |
| xbimg | 100 | — |
| xbdoc | 100 | 0（默认） |
| 其他插件 | 0（默认） | 0（默认） |

⇒ **xbnext 一定排在 xbdoc / xbimg 之前**：先清洗、后注入。

两个附带结论（都已写成 `tests/test_coexist.py` 的断言）：

1. 内置星标已经用 `event_message_type(ALL)` 把 `is_wake` 对**每条消息**置真
   （`waking_check/stage.py::passed → is_wake = True`），所以本插件再注册一个
   **不会**引入"bot 回每条消息"的新行为；真正决定是否调 LLM 的
   `event.is_at_or_wake_command` 只由「@bot / 唤醒前缀 / 私聊设置」赋值。
2. `event.call_llm = True` 的语义是**禁止**默认 LLM（`should_call_llm` 的
   docstring），不是"强制调用" —— 早期钩子的守卫只需要判
   `is_at_or_wake_command`。

### 2.2 两个入口的执行阶段

```
waking_check ──► whitelist ──► ratelimit ──► contentsafety ──► preprocess ──► process
                                                                                  │
   ① event_message_type(ALL) 钩子在这里跑（StarRequestSubStage，priority=1000）  │
      └─ core 还没算 has_valid_message → 可以改写 event.message_str             │
                                                                                  ▼
   ② on_llm_request 钩子在这里跑（agent_sub_stage 里 call_event_hook）
      └─ req 已经建好（req.prompt = event.message_str，astr_main_agent.py L1491）
```

顺序保证：① 跑在 ② 之前 ⇒ 早期钩子补写的正文会原样进入 `req.prompt`。

### 2.3 `on_llm_request` 内的固定执行顺序（单点、可测）

```
1. switches 对账（读配置，幂等 install/terminate 各模块开关）
2. image_slim      —— 历史旧图换占位（R8，省输入 token）
3. quote_clean      —— 先把无效引用/死路径清掉（后面的注入不再看见垃圾）
4. face_translate   —— 表情翻译（可能补写 prompt 或追加说明）
5. reply_attribution—— 回复指向三方说明（依赖本轮引用状态）
6. user_profile     —— 当前发言人档案（最后注入，保证不被前面清洗误伤）
```

理由：清洗类在前、注入类在后；档案最后注入 → 它绝不会被本插件自己的清洗删掉。

### 2.4 日志纪律（真机第二轮反馈：「日志没看到 …但是这样有点乱」）

| 级别 | 什么时候打 | 形态 |
| :--- | :--- | :--- |
| INFO | `on_loaded` / `terminate` | `已加载 …` / `已卸载` |
| INFO | **本轮至少一个功能真有动作** | `本轮 引用占位清洗·改写正文、用户档案·注入1段` |
| INFO | 早期钩子补写了正文 | `纯表情补写正文：[表情:得意]` |
| INFO | 撤回命中在飞任务 | `撤回命中：已取消在飞请求（消息 12345）` |
| WARNING | 单功能抛异常 | `<key> 执行失败：…`（不冒泡） |
| DEBUG | 仅 `debug_log` 打开 | `ctx.notes` 逐条（跳过原因 / 注入字数…） |

**没动作就一行不打** —— 正常请求不会把日志刷屏，要看明细再开 `debug_log`。
汇总行的五个动作标签：`注入N段`（`ctx.injected` 前后差）、`改写正文`
（`req.prompt` 前后不等）、`清洗N块`（`ctx.parts_cleaned` 前后差，
R2 清洗 `extra_user_content_parts`）、`清图a→b`（`req.image_urls` 条数变化）、
`瘦历史图N张`（`ctx.slimmed_images` 前后差，R8）。

### 2.5 与 xbdoc / xbimg 共存（`tests/test_coexist.py`）

| 维度 | xbdoc | xbnext |
| :--- | :--- | :--- |
| 注入通道 | `extra_user_content_parts` append（缺 TextPart 时回退拼 `req.prompt`） | 同（append） |
| `req.system_prompt` | 会替换（`apply_system_prompt`） | **绝不碰** |
| `req.contexts` | 不碰 | 仅 R8 开启时把历史旧图换占位（只动图片成分、不改文本；**默认关 = 不碰**） |
| 执行先后 | 100 / 0 | 1000 ⇒ **先跑** |

⇒ 两者是"先清洗 → 后注入"的关系，谁也不会删掉对方已放进 `extra_user_content_parts`
的内容（`inject_text` 只 `append`）。`quote_clean` 对内容块的清洗
（`clean_parts`，第六轮新增）**只重写命中占位符的文本**：xbdoc 的 `【参考资料】` 块不含占位符
⇒ 原样保留、对象引用不变；未命中的他方 part 一律不动（`test_coexist.py` 整轮锁死）。

## 3. 注入协议（全插件统一）

`xbnext/injector.py` 是**唯一**允许构造 `extra_user_content_parts` 的地方：

```python
def make_temp_part(text: str) -> TextPart:
    """构造 mark_as_temp 的 TextPart；统一标签前缀 <xbnext>。"""

def sanitize(text: str, max_len: int = 128) -> str:
    """控制字符→空格、去零宽、<>全角化、压空白、截断。"""

def strip_xbnext(text: str) -> str:
    """清洗模型输出/历史里残留的 <xbnext> 标记（兜底，正常应不落库）。"""
```

规则（红线）：
- 一律 `mark_as_temp()`（不写历史）；
- 一律走 `injector`，禁止各模块自行 `TextPart(...)`；
- 身份/档案类字段必须过 `sanitize`；
- 不改 `req.system_prompt`（保护 prompt cache）。

## 4. 开关模型

`_conf_schema.json` 每功能一个 bool 主开关 + `condition` 联动子项
（照抄 AstrNa 模式，见 research/astrna.md §F）：

```json
{
  "enable_face_translate":   {"type": "bool", "default": true,  ...},
  "enable_quote_clean":      {"type": "bool", "default": true,  ...},
  "enable_reply_attribution":{"type": "bool", "default": false, ...},
  "enable_user_profile":     {"type": "bool", "default": false, ...}
}
```

默认值策略：**纯修正类（R2/R3）默认开，新增行为类（R1/R4）默认关** ——
与 AstrNa"全部默认关"不同，因为 R2/R3 修的是明确 bug，不开启反而留 bug；
但要在 hint 里写清"开启后会改写本轮请求"。

`runtime.py::sanitize_request()` 每请求对账一次（AstrNa 验证过的模式），
配置热改无需重启。

## 5. 持久化

| 数据 | 载体 | 键/路径 | 备注 |
| :--- | :--- | :--- | :--- |
| R1 回复指向索引 | 插件 KV | `xbnext:reply_targets:<umo>` | 上限每会话 50 条（P16 起，默认 200→50）/ 全局 200 会话（P15），超限连数据带索引一起删 |
| R4 用户档案 | 插件 KV | `xbnext:profile:<platform>:<uid>` | 量大时迁移 `data/plugin_data/astrbot_plugin_xbnext/profiles.json` |
| R3 表情映射 | 内置表 + overlay | `xbnext/features/face/data.py::QQ_FACE_ALL`（内置优先）+ 插件 KV `xbnext:face_overlay`（运行时补缺），格式由 `face_format` 控制 | **594 条权威全量表**（发布时由 `gen_face_table.py` 生成），QQ 出新表情靠 `face_auto_update` 循环补进 overlay |
| P16 注入记录 | 插件 KV | `xbnext:inject_log` | 最近 **10 轮**新在前（`MAX_ITEMS=10`），截断 正文 8000 / 段 4000 / 24 段；每轮 LLM 请求收尾写入，`GET /inject_log` 只读展示 |
| WebUI 偏好 | 服务端配置 | `config/save` 存 `ui_theme_mode` 等 | iframe 禁 localStorage |

KV 要求：**懒加载 + 内存缓存 + 写穿**；所有 KV 异常降级为"无数据"，不裸抛。

### 5.1 R3 表情表的三层结构与自动更新

| 层 | 载体 | 说明 |
| :--- | :--- | :--- |
| 内置表 | `face/data.py::QQ_FACE_ALL`（594 条） | 发布时由 `gen_face_table.py` 生成，**查表优先** |
| overlay | 插件 KV `xbnext:face_overlay` → `{"ids": {...}, "updated_at": iso}` | 运行时拉权威源算出的缺口，**只补内置表没有的 ID** |
| 查询入口 | `face/updater.py::face_name_with_overlay()` | 内置 → overlay 依次查；`service.translate_token` 唯一走这里 |

更新循环（`FaceFeature.on_load` 启动 / `on_unload` 取消，细节在 `face/__init__.py`）：

- **权威源**：`koishijs/QFace` 的 `public/assets/qq_emoji/_index.json`
  （QQ 官方表情资源索引，实测 537 条、数字 emojiId 覆盖到 507）；
- **首拉**：KV 里从未更新过（`updated_at` 为空）→ 启动约 1 分钟后先拉一次
  （拿新版表情不用等凌晨）；已更新过 → 走每日排程；
- **排程**：按 `face_update_time`（默认 `04:30`，本地时区）每天拉一次；
  距离下个时间点超过 1 小时就分段睡（`SLEEP_SEGMENT=3600`），每段醒来重读配置 ⇒ 热改最迟 1 小时生效；
- **门禁**：`enable_face_translate` 与 `face_auto_update` 都开才 fetch；
  门禁只挡拉取、**循环常驻**（配置热开无需重启，下次醒来即生效）；
- **落库**：成功 → overlay 整体替换成"权威源 − 内置表"的缺口集并写 KV，
  有新增打一条 INFO，无变化打 DEBUG；KV 写失败仅 WARNING（本会话仍有效）；
  拉取失败打 WARNING、**不动 `updated_at`**（下次排程点重试）；
- **红线**：任务首次动作必是 ≥60s 的 sleep（`FIRST_RUN_DELAY` / `SLEEP_SEGMENT` / `max(delay, 60)`），
  保证单测里 `asyncio.run` 退出时任务被取消、**永不触网**；
  网络只走 `asyncio.to_thread(urllib)` 不阻塞事件循环；
  **异常一律不上抛**（AstrBot 官方原则 4），`CancelledError` 原样抛出以便取消。

## 6. 与 AstrNa 的关系（**不做共存让路**）

- XBNEXT **不检测 AstrNa、也不让路**。早期设计写过 `switches.detect_astrna()` /
  `runtime.conflict_for()` 与 WebUI 的「AstrNa 共存」卡片，**已整套移除**。
  理由：AstrNa 没装时那张卡永远是 `—`（假功能位）；而"开关开着却不生效"
  会让排查变盲。
- 两个插件同装时**各自独立工作**，不互相读配置、不互相让路；
  是否重叠（如 R1 与 `optimize_reply_target_history` 同开）由用户自己关一个。
- AstrNa 仍是**路线参考**（R1 的 KV 索引 + 三方中文说明、R4 的 sanitize 红线），
  README 致谢保留；但代码里**没有任何运行时探测**。

## 7. 测试策略

- 本机无 AstrBot 本体 → **纯逻辑抽离**：每个功能的 core 函数（`features/*/service.py`
  与 `features/*/store.py`）不 import astrbot，输入输出用普通 dict/str/list，
  `tests/` 可直接跑。
- **跑法**：`python -X utf8 -m unittest discover -s tests`
  （本机没装 pytest，统一用标准库 unittest；`tests/conftest.py` 提供
  `FakeReq` / `FakeEvent` / `FakeTextPart` / `FakeKV` 四个假对象）。
- 每个 R 一个测试文件：
  `test_quote_clean.py` / `test_face.py` + `test_face_update.py`（R3 自动更新）/
  `test_stores.py`；
  另有 `test_structure.py`（版本同步、schema 完整性、功能注册表一致性、
  **全包可导入**——抓相对导入层级错误）、`test_injector.py`（清洗 + 注入）、
  `test_coexist.py`（**与 xbdoc 共存**：优先级、`【参考资料】` 不被清洗、
  注入只 append、`system_prompt`/`contexts` 不动、INFO 汇总日志），
  以及 `test_main_smoke.py`（用 stub 顶替 `astrbot.api` 装载 `main.py`，
  验证钩子/指令接线与"单功能炸掉不拖垮请求"）。
- **胶水层（`runtime.py`）的覆盖**：生命周期 + 一轮请求 + 故障隔离由
  `test_main_smoke.py` 覆盖；早期钩子（`handle_adapter_message`）由
  `test_face.py::TestRuntimeAdapterHook` 覆盖；INFO 汇总日志由
  `test_coexist.py::TestFullRoundCoexist` 覆盖 —— 刻意不重复造用例。
