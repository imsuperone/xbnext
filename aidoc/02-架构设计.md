# XBNEXT · 架构设计

> 版本：v0.1（设计稿，随实现更新）
> 原则：干净、精简、规范；每个模块单一职责；所有 LLM 注入走统一通道。

---

## 1. 分层结构

> 本节与仓库实际结构保持一致（P1 已落地）。**改结构必须同步改这里。**

```
astrbot_plugin_xbnext/
├─ main.py                 Star 入口：装配 runtime、注册钩子与指令（薄壳，只转发）
├─ metadata.yaml           插件元数据（含 pages 声明；**版本号唯一来源**）
├─ _conf_schema.json       配置 schema（每功能一个 enable_* 主开关 + condition 子项）
├─ xbnext/                 业务包
│  ├─ __init__.py          版本号（读 metadata.yaml）、PLUGIN_NAME、HOOK_PRIORITY
│  ├─ runtime.py           调度中心：每请求对账开关、按固定顺序调用各功能
│  ├─ context.py           RequestContext：单次请求上下文（功能只跟它打交道）
│  ├─ injector.py          统一注入工具：temp part 构造 + sanitize + strip + wrap
│  ├─ switches.py          开关对账 + AstrNa 冲突检测（让路判断）
│  ├─ storage.py           插件 KV 封装：前缀 / 缓存 / 写穿 / 异常降级
│  ├─ config.py            配置读取（含 _conf_schema.json 默认值回退）
│  ├─ features/            ★ 功能模块 —— **一功能一目录，新增功能只改这里**
│  │  ├─ base.py           Feature 基类 + 扩展步骤说明
│  │  ├─ __init__.py       注册表 FEATURES（加功能 = 这里加一行）
│  │  ├─ quote/            R2 引用占位清洗  （service.py 纯逻辑 + __init__.py 功能类）
│  │  ├─ face/             R3 QQ 表情翻译   （service.py 纯逻辑 + data.py 表情表）
│  │  ├─ attribution/      R1 回复指向索引  （store.py KV 索引）
│  │  └─ profile/          R4 用户档案      （store.py 档案存取 + 渲染）
│  └─ web/                 WebUI 后端 API（ping / state）
├─ pages/manager/          R5 WebUI（xbimg 形态：index.html + style.css + api.js + app.js）
├─ tests/                  单测（unittest，**不依赖 astrbot**）
└─ aidoc/                  本文档（不进发布包，必须进 git）
```

**为什么功能用目录而不是单文件**：功能会长大（R1 要 store + 注入文案、
R3 要 service + 权威表情表、R4 要 store + 指令），单文件会膨胀到 AstrNa
那种 40-80KB 大文件。一功能一目录后，每个功能自成一块，拆分边界天然清晰。

**新增功能的 5 步**（写在 `features/base.py` 顶部注释里）：

1. 建 `features/my_thing/`，写 `class MyThingFeature(Feature)`；
2. 填 `key` / `name` / `description` / `order`，实现 `on_llm_request`；
3. `_conf_schema.json` 加 `enable_my_thing`；
4. `features/__init__.py` 的 `FEATURES` 加一行实例化；
5. `tests/` 加 `test_my_thing.py`。

第 3、4 步有机械校验兜底（`tests/test_structure.py`：功能 key 必须在 schema 里、
schema 的 `enable_*` 必须有对应功能、执行顺序必须升序），漏做直接红。

## 2. 钩子与调用时序

XBNEXT 用到的 AstrBot 钩子（全部 `priority` 统一用一个常量，建议 100，
**低于** AstrNa 的 1000 → 让 AstrNa 先跑、我们后跑；具体数值 P1 实测后定）：

| 钩子 | 用途 | 所属模块 |
| :--- | :--- | :--- |
| `@filter.on_llm_request` | 主战场：表情翻译、引用清洗、身份/档案注入、回复指向说明 | 全部 |
| `@filter.event_message_type(ALL)` | 采集 bot 回复的"回给谁"（结合 after_message_sent） | R1 |
| `@filter.after_message_sent` | 记录本轮 bot 回复 → 写回复指向索引 | R1 |
| `@filter.on_astrbot_loaded` | 初始化存储、加载映射表 | 全部 |
| `@filter.command_group` | `/xbnext ...` 指令组（档案自助等） | R4 |
| `terminate()` | 卸载时释放资源 | 全部 |

**`on_llm_request` 内的固定执行顺序**（单点、可测）：

```
1. switches 对账（读配置，幂等 install/terminate 各模块开关）
2. quote_clean      —— 先把无效引用/死路径清掉（后面的注入不再看见垃圾）
3. face_translate   —— 表情翻译（可能补写 prompt 或追加说明）
4. reply_attribution—— 回复指向三方说明（依赖本轮引用状态）
5. user_profile     —— 当前发言人档案（最后注入，保证不被前面清洗误伤）
```

理由：清洗类在前、注入类在后；档案最后注入 → 它绝不会被本插件自己的清洗删掉。

## 3. 注入协议（全插件统一）

`xbnext/injector.py` 是**唯一**允许构造 `extra_user_content_parts` 的地方：

```python
def make_temp_part(text: str) -> TextPart:
    """构造 mark_as_temp 的 TextPart；统一标签前缀 <xbnext>。"""

def sanitize(text: str, max_len: int = 128) -> str:
    """控制字符→空格、去零宽、<>全角化、压空白、截断。"""

def strip_xbnext(text: str) -> str:
    """清洗模型输出/历史里残留的 <xbnext> 标记（兜底，正常应不落库）。"""
```

规则（红线）：
- 一律 `mark_as_temp()`（不写历史）；
- 一律走 `injector`，禁止各模块自行 `TextPart(...)`；
- 身份/档案类字段必须过 `sanitize`；
- 不改 `req.system_prompt`（保护 prompt cache）。

## 4. 开关模型

`_conf_schema.json` 每功能一个 bool 主开关 + `condition` 联动子项
（照抄 AstrNa 模式，见 research/astrna.md §F）：

```json
{
  "enable_face_translate":   {"type": "bool", "default": true,  ...},
  "enable_quote_clean":      {"type": "bool", "default": true,  ...},
  "enable_reply_attribution":{"type": "bool", "default": false, ...},
  "enable_user_profile":     {"type": "bool", "default": false, ...}
}
```

默认值策略：**纯修正类（R2/R3）默认开，新增行为类（R1/R4）默认关** ——
与 AstrNa"全部默认关"不同，因为 R2/R3 修的是明确 bug，不开启反而留 bug；
但要在 hint 里写清"开启后会改写本轮请求"。

`runtime.py::sanitize_request()` 每请求对账一次（AstrNa 验证过的模式），
配置热改无需重启。

## 5. 持久化

| 数据 | 载体 | 键/路径 | 备注 |
| :--- | :--- | :--- | :--- |
| R1 回复指向索引 | 插件 KV | `xbnext:reply_targets:<umo>` | 上限每会话 200 条 / 全局 300 会话，LRU 淘汰 |
| R4 用户档案 | 插件 KV | `xbnext:profile:<platform>:<uid>` | 量大时迁移 `data/plugin_data/astrbot_plugin_xbnext/profiles.json` |
| R3 表情映射 | 内置 + 配置覆盖 | `xbnext/features/face/data.py::QQ_FACE`，格式由 `face_format` 控制 | **样例表，P2 必须补权威全量表** |
| WebUI 偏好 | 服务端配置 | `config/save` 存 `ui_theme_mode` 等 | iframe 禁 localStorage |

KV 要求：**懒加载 + 内存缓存 + 写穿**；所有 KV 异常降级为"无数据"，不裸抛。

## 6. 与 AstrNa 共存策略

- 假定用户可能同时装 AstrNa（它默认全关，但用户会开）。
- `switches.py::detect_astrna()`：尝试导入 `astrna.runtime` 并读其开关状态
  （`optimize_reply_target_history` / `optimize_quoted_image_input` /
  `optimize_identity_metadata`）。
- 冲突矩阵：

| AstrNa 开着 | XBNEXT 行为 |
| :--- | :--- |
| `optimize_reply_target_history` | R1 的"三方说明注入"让路（不重复注入）；R1 的"历史发言人标记"仍可独立开 |
| `optimize_quoted_image_input` | R2 只做占位符文本翻译与死路径过滤（它做恢复、我们做清洗，互补不冲突） |
| `optimize_identity_metadata` | 无冲突（R4 注入的是档案，不是身份 JSON） |
| 导入失败 / 版本不符 | 按"未安装"处理，XBNEXT 独立工作 |

检测结果要打进日志与 WebUI 状态面板，方便排查"为什么没生效"。

## 7. 测试策略

- 本机无 AstrBot 本体 → **纯逻辑抽离**：每个功能的 core 函数（`features/*/service.py`
  与 `features/*/store.py`）不 import astrbot，输入输出用普通 dict/str/list，
  `tests/` 可直接跑。
- **跑法**：`python -X utf8 -m unittest discover -s tests`
  （本机没装 pytest，统一用标准库 unittest；`tests/conftest.py` 提供
  `FakeReq` / `FakeEvent` / `FakeTextPart` / `FakeKV` 四个假对象）。
- 每个 R 一个测试文件：
  `test_quote_clean.py` / `test_face.py` / `test_stores.py`；
  另有 `test_structure.py`（版本同步、schema 完整性、功能注册表一致性、
  **全包可导入**——抓相对导入层级错误）、`test_injector.py`（清洗 + 注入），
  以及 `test_main_smoke.py`（用 stub 顶替 `astrbot.api` 装载 `main.py`，
  验证钩子/指令接线与"单功能炸掉不拖垮请求"）。
- **胶水层（`runtime.py`）没有独立测试**：它的行为已被 `test_main_smoke.py`
  覆盖（生命周期 + 一轮请求 + 故障隔离），刻意不重复造用例。
